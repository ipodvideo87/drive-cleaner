## Project shape

This is a Python command-line utility for Windows that uses WizTree or WinDirStat exports. `python drive_cleaner.py` opens a guided menu for scanning, analysis, and backup management. Automated WinDirStat scanning requires 2.6.0 or later. It is not yet a signed installer or desktop GUI. The primary user flow is scan → review report → choose files/folders → choose a backup or skip it → confirm → cleanup; restore is available when a verified backup was made.

## Current capabilities

- Saved-backup deletion reports entry counts while checking for links and junctions and a periodic heartbeat during longer removals. Ctrl+C during the check confirms that nothing was removed; a failed or interrupted removal warns that the backup may be incomplete. Bulk deletion stops after an interrupted backup and leaves later backups untouched.

- Guided cleanup and manual-review selection use the Up/Down arrow keys to move the highlight, Spacebar to select or clear exact files and folders, and Enter to finish. Picks stay checked while changing pages or filters. Press `D` on a highlighted folder to browse its saved scan entries; in that nested list, Enter or `D` keeps the picks, while `B`, Esc, or `Q` returns without adding them. Earlier main-list picks remain selected. `A` selects suggestions in the main list only. Numbered input remains available when the terminal cannot support the keyboard picker; reopening a folder shows its previous nested picks checked so users can revise them. Reports and picker rows label each target as File or Folder and explain that protected data and detected projects remain untouched.
- Interactive prompts spell out what numbered choices, letter shortcuts, Enter defaults, and cancellation do. Scanner descriptions are neutral. The WizTree menu explains that Automatic picks Fast only for a whole drive in an Administrator terminal, Fast is limited to a whole drive and needs Administrator access, and Standard works without it but may miss files the account cannot access. README and guide use the same descriptions.
- Scan reports separately list up to 100 of the largest current, unprotected files that did not match automatic cleanup rules. Protected locations, project files, linked paths, and missing files are filtered before the bounded shortlist is built, so ineligible large entries cannot crowd eligible files out. This list is excluded from suggested-space totals, is never auto-selected, and can only create a manual-review plan after exact individual-file selection and the typed `REVIEWED` acknowledgement; folder and bulk selection are disabled. Generated plans preserve normal target rechecks, optional verified backup, and final cleanup confirmation.
- Guided single-command menu starts with an original ASCII space-map welcome screen, a short scan-to-clean workflow, and a clear statement that scans and reviews do not delete files; menu choices remain visible immediately below. It explains that choosing a folder includes unlisted files and subfolders, while protected/project data and higher-risk items remain unless deliberately selected. The menu covers scanning, previous-scan review, and backup management; scan option prompts retry invalid yes/no and numeric input and support explicit cancellation. The review menu, direct analyzer, and backup confirmations cancel cleanly on Ctrl+C or end-of-input.
- Project detection protects caches under VS Code `.vscode` workspace folders, alongside `*.code-workspace` files, and in folders with AI project guidance or settings such as `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `SKILL.md`, `.cursorrules`, `.cursor`, `.claude`, `.github`, or `copilot-instructions.md`, including nested cleanup-plan checks. It also recognizes common Python requirement lists, including `requirements-dev.txt` and `requirements-test.in`, without treating shared requirement lists at the profile root as a project. Shared guidance/settings and `.gitignore` at the profile root do not make the entire user profile a project; `.git` still does. The profile-level `.vscode` extensions directory remains protected.
- Agent/editor settings folders `.claude`, `.cursor`, `.gemini`, `.github`, `.opencode`, and `.windsurf` are excluded from cleanup suggestions because they can hold authentication, user settings, history, and project instructions; close names such as `.cursorBackup` still follow normal review rules.
- Scans started with the direct `scan.py` command are saved into the same previous-scan list; completion points users to the guided menu instead of suggesting a second analyzer command.
- After a guided scan, Enter opens the review and `N` returns to the main menu with the scan saved. This prompt is Yes/No because a separate `Q` action would do the same thing as `N`; invalid answers are retried. Numbered menus use one `0` choice to exit or return. Cleanup item-number prompts use Enter alone to cancel, without repeating the same action with `Q`.
- The previous-scan picker lists validated current and recognized legacy exports newest first, supports numeric selection and pagination, and keeps manual path entry for other supported CSVs. It accepts files only; missing, changed, or unreadable scans return the user to scan selection with a clear message instead of a traceback.
- WizTree 3.18+ and WinDirStat 2.6+ scanning, selectable at the prompt or with `--app`; both auto-detected through environment variables, local folders, common install paths, and `PATH`. The guided menu shows the detected executable and defaults to using it, while allowing users to choose another validated installed or portable `.exe` for that scan; if discovery fails, it asks for a full path. WizTree export options are version-gated; a requested finite depth is refused when a known version is older than 4.02. An unreadable version produces a warning. Direct scanner commands continue to use `WIZTREE_PATH` or `WINDIRSTAT_PATH`; scanner discovery normalizes quoted environment-variable values and paths with spaces. Scans accept a drive root or existing absolute local folder.

Version 4.02+ adds requested depth limits, 4.13+ adds allocation sorting, and 4.25+ adds drive-capacity metadata; missing capacity metadata is labeled as current disk usage during analysis.
