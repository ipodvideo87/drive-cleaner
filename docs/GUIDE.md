# Drive Cleanr user guide

Drive Cleanr is a conservative Windows cleanup workflow. WizTree or WinDirStat scans a drive or folder, then Drive Cleanr lists suggestions for review. You choose individual files, folders, or both for the cleanup plan. Choosing a folder also includes its contents, even when they are not separate scan suggestions. Protected paths and detected projects are kept. Higher-risk candidates are kept unless you explicitly select a listed nested candidate too; the preview calls out that choice. Agent/editor settings and authentication state are also protected. The preview shows up to 12 direct items; other contents may also be removed. You can choose whether to make a verified recovery backup before cleanup.

## 1. Install and scan

Drive Cleanr accepts fixed drives, removable drives, RAM disks, and folders on those volumes. It refuses UNC and mapped network drives. Scan review skips entries from network or unavailable drives, and generated cleanup plans check the drive type again before backup or cleanup. If a drive letter changes to a network or unavailable volume after review, the plan stops before it creates a backup or removes anything.

Install Python 3.10+, have Windows PowerShell 5.1 (included with Windows) or PowerShell 7 available for generated cleanup plans, and have either WizTree or WinDirStat available. Automated WizTree CSV scans require version 3.18 or newer; WinDirStat scans require version 2.6.0 or newer. WizTree depth limits require 4.02 or newer, allocation sorting requires 4.13 or newer, and drive-capacity details require 4.25 or newer. When Windows reports the version, Drive Cleanr adds optional settings only when that version supports them. A requested depth limit is refused on known versions older than 4.02; choose unlimited depth or update WizTree. If Windows cannot read the version, Drive Cleanr warns and tries the basic export; it also tries a requested depth limit but cannot confirm that the option is supported. Standard WizTree scans can run without Administrator access; only its Fast full-drive method requires an Administrator terminal. NTFS is a common Windows file system; Fast reads its file table directly, while other file systems use normal Windows scanning. Standard WizTree and WinDirStat scans may miss files this account cannot access.

Both scanners are supported choices; the menu does not rank one above the other. WinDirStat uses its standard scan and does not require Administrator access, though it can only show files this Windows account can access. For a whole drive, WizTree offers three methods: **Automatic** has Drive Cleanr choose Fast when this terminal has Administrator access, and Standard otherwise; **Fast full-drive** requires a whole drive plus Administrator access and reads the file table directly on NTFS (a common Windows file system), while other file systems use normal Windows scanning; **Standard** uses normal Windows file access, works on drives or folders without Administrator access, and may take longer or miss files this account cannot access. Administrator access means opening PowerShell with **Run as administrator**. When a scanner is found, press Enter or type `Y` to use it, type `N` to choose another scanner program (`.exe`) for this scan, or type `Q` to cancel scan setup.

Drive Cleanr supports the official portable versions of [WizTree](https://diskanalyzer.com/download) and [WinDirStat](https://github.com/windirstat/windirstat/releases). For WinDirStat, use 2.6.0 or newer; this project uses the `/SaveTo` form. WizTree versions older than 3.18 cannot make the command-line CSV export Drive Cleanr needs. When the guided menu finds a scanner, it shows its path; press Enter to use it or choose another installed or portable `.exe` for this scan. If it cannot find one, enter the full path to its `.exe` file. Direct `scan.py` use can select a portable executable through `WIZTREE_PATH` or `WINDIRSTAT_PATH`; quoted values and paths with spaces are accepted. WinDirStat follows its saved filters, exclusions, and other scan settings, which can leave files out of results; review those settings before expecting a full scan.

Start the guided workflow with:

```powershell
python drive_cleaner.py
```

Choose **Scan a drive or folder**, then select WizTree or WinDirStat and enter the scan target and time limit. If Drive Cleanr cannot find the selected scanner, enter the full path to its `.exe` file or press Enter to cancel. With WizTree, choose whether results should include individual files as well as folders. This is on by default; if you choose folders only, individual files cannot be selected later. Invalid answers are re-prompted; enter `Q` at an option prompt to cancel setup. The menu can open the completed scan for review. Scans started directly with `scan.py` also appear under **Review a previous scan** in the main menu. For direct `scan.py` use, set `WIZTREE_PATH` or `WINDIRSTAT_PATH` if an executable isn't found automatically.

Scans can include individual files as well as folders so large files can be reviewed and selected on their own. The default timeout is 30 minutes; for a larger or slower drive, increase it with `--timeout 3600`. The wait message shows the time limit in seconds, minutes, or hours. While the scanner runs, progress shows elapsed time and how much of the scan file has been saved. After the scanner exits, Drive Cleanr checks that the export has finished saving; if the file has not appeared or is still empty, it reports that status every few seconds while it waits. A scan is ready only after the results file is stable and passes validation. After a successful scan, press Enter to open its review, or enter `N` to return to the main menu and review it later; the scan remains saved. Invalid answers are retried. If a scan is cancelled or fails, Drive Cleanr tries to stop the scanner before removing its incomplete export. If it cannot confirm that the scanner stopped or Windows prevents removal, Drive Cleanr reports that the export was preserved and shows its location; incomplete exports are never offered for review. WinDirStat follows its saved filters, exclusions, and other scan settings, which can leave files out of results; review those settings before scanning a whole drive. Drive Cleanr also checks each file's current byte length against the scan and skips candidates if the size changed or cannot be checked; rescan to refresh them.

Scans retain earlier exports and review plans. To free space used by old scan results, choose **Manage saved scans** from the main menu, enter how many of the newest exports to keep, review the exact older scan files and any verified paired cleanup-plan paths, and type `DELETE OLD SCANS` to confirm. Press Enter at the keep-count prompt to cancel. This removes only validated Drive Cleanr scan exports. Immediately before removal, Drive Cleanr revalidates each scan or paired plan through the same open file it will remove, while keeping its folder path from being redirected. A changed file or new link/junction is preserved; an outside file cannot be removed through a swapped junction. A cleanup plan is removed only when its generated header matches that exact scan export; user-authored scripts and older plans without this marker are kept. Removing scan history does not remove files or folders listed in a scan. Unrelated CSV files and PowerShell scripts are left alone. For direct command-line automation, `scan.py --cleanup --keep-latest <number>` remains available.

## 2. Review the scan

```powershell
python analyze.py --tui
```

Choose a saved scan from the numbered list, shown newest first. Enter `N` or `P` to browse older or newer pages; enter `M` to provide the path to another supported scan CSV, or `0` to return to the main menu. Validated scans from older Drive Cleanr filename formats and folder layouts are included. The picker accepts files, not folders. If a scan is missing or cannot be read, Drive Cleanr explains the problem and lets you choose another scan. Press Ctrl+C or close terminal input to cancel the review; no cleanup starts. Review the disk summary and the suggested files and folders, including each exact path, size, and reason it was listed. You can view all suggestions, save the list to a text file, change the minimum item size, or create a cleanup plan. To review a specific scan from the command line, run `python analyze.py .\data\scan.csv --min-size 50 --list-items`.

The report shows when the scan file last changed. Files and folders can change after a scan; scan again before creating a cleanup plan if anything may have changed.

The report separately lists up to 100 of the largest scanned files that did not match an automatic cleanup rule. They are for investigation only; Drive Cleanr does not know whether they are needed, and their sizes are excluded from the suggested-space estimate. Protected locations, linked paths, detected projects, and files that are no longer present are filtered before ranking, so excluded large entries do not hide other files. Choose **Review the largest files outside cleanup suggestions** to select individual files by exact path. Folders and bulk selection are disabled in this list. Type `REVIEWED` to create a plan for the selected files; the plan still shows the exact paths and asks for the usual backup choice and final cleanup confirmation. Choose only files you recognize and no longer need.

Each selectable entry is labeled **File** or **Folder** and shows its exact path, size, and reason. In an interactive Windows terminal, use the **Up/Down arrow keys** to move the highlight, press **Spacebar** to select or clear that row, and press **Enter** to finish; selections stay checked when you change pages. Use **PageUp/PageDown** or `N`/`P` to change pages and `F` to filter by name or path. Press `D` while a folder is highlighted to browse its saved scan entries; the same arrow-key and Spacebar controls select exact files or subfolders. Folder browsing keeps the review level you chose. Choose **All review levels** before opening a folder if you also want to see entries assigned to more cautious levels. Press **Enter or D** to add those folder picks to the cleanup-plan selection. Press **B, Esc, or Q** to return without adding them; selections already made in the main list stay selected. Selections are shared between the main list and folder browsing, so the same file or folder is one plan entry and toggling it in either view updates that selection. The keyboard picker shows the item checked in both views; numbered selection shows checks in the folder browser and reports the current selection count when you keep its picks. `A` selects every suggestion in the main list only; it does not select hidden entries inside folders. If arrow-key controls are unavailable, enter item numbers to select or clear rows. Reopening a folder shows its previously selected entries checked so you can revise the selection. If a scan did not include file rows, individual files cannot be selected; scan again with individual files enabled. Choosing a folder includes its files and subfolders that pass safety checks. Protected data, detected projects, and higher-risk candidates you did not select stay in place.

High, medium, and low are review levels, not a guarantee of safety. Only standard Windows/user temp roots and the configured `TEMP`/`TMP` locations receive the lower-risk temporary-files label. The recognized temp root itself is omitted so qualifying items inside it can be reviewed and selected individually; folders merely named `Temp` or `Tmp` elsewhere stay in the caution tier. Read [the knowledge base](../references/knowledge.md) before approving unfamiliar targets. Folder sizes may include data that the cleanup plan keeps, so actual free-space gains can be smaller.

Drive Cleanr checks each file or folder against the current filesystem. WinDirStat localizes CSV column names with its interface language; Drive Cleanr recognizes the documented scan layout and keeps its own prompts and reports in English. If WinDirStat did not include reliable type information, Drive Cleanr checks the current path. If the scan's reported type conflicts with the current path, that entry is skipped and counted in the report; rescan to refresh it.

Entries with hidden formatting or terminal-control characters in their paths are skipped and counted. Such characters can make a path appear to name a different file or folder in a terminal.

When a path matches both a broad cache rule and a recognized package-manager rule, Drive Cleanr uses the more specific package-manager label and caution level.

Crash-dump rules only apply under the drive's `Windows` directory, not to user archives or project folders with similar names. They appear at the caution level because dumps can help investigate crashes and some types can contain memory data; keep them while troubleshooting or waiting for support.

Cache-like paths inside recognized projects are omitted from cleanup candidates. Project markers include common manifests and Python requirement lists such as `requirements-dev.txt`, `requirements-test.in`, `dev-requirements.txt`, and `dev-requirements.in`; Node's `npm-shrinkwrap.json` lockfile; Git metadata and files such as `.git`, `.gitignore`, and `.gitattributes`; project guidance files such as `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `SKILL.md`, `.cursorrules`, and `copilot-instructions.md`; agent/editor settings folders such as `.claude`, `.cursor`, `.gemini`, `.github`, `.opencode`, and `.windsurf`; IDE workspace folders such as `.idea`, `.vscode`, and `.vs`; VS Code `*.code-workspace` files; Dev Container settings (`.devcontainer/` or `.devcontainer.json`); Windows Sandbox `*.wsb` configuration files; Unreal descriptors (`.uproject` and `.uplugin`); Godot `project.godot`; Unity `ProjectSettings`; Helm chart metadata (`Chart.yaml`); Visual Studio project/solution files; .NET `global.json` and MSBuild `Directory.Build.*`/`Directory.Solution.*` files; Swift and CocoaPods manifests; Xcode `.xcodeproj` and `.xcworkspace` bundle directories; Bazel workspace/build files; Nix flakes; Terraform `.tf`/`.tfvars` files; Zig `build.zig` and `build.zig.zon`; Haskell `stack.yaml`, `cabal.project`, and `.cabal` package files; OCaml `dune-project`, `dune-workspace`, and `.opam` package files; and Clojure `deps.edn` or Leiningen `project.clj` files. The analysis report lists detected project roots and the marker that caused candidate paths there to be skipped, when available. VS Code's user-profile `.vscode` extension folder is protected, but it does not mark the whole profile as a project; a `*.code-workspace` file stored directly at the profile root has the same project-detection exception. A `.wsb` file stored directly at the profile root also does not mark the whole profile as a project. Shared editor and AI-assistant guidance files and settings folders, `.gitignore`, .NET SDK/MSBuild settings, and common Python requirements lists at the profile root are also ignored as project markers; `.git` at that root still marks it as a project. For a project with no recognized marker, add an empty `.drive-cleanr-protect` file at its root.

Generated cleanup plans check the active USERPROFILE directory for project markers, then stop walking to parent directories. A project marker above a relocated profile does not make files inside that profile part of the project.

## 3. Choose what to clean and create a plan

In the review menu, choose which review group to include, then choose the listed files, folders, or both. Every row is labeled **File** or **Folder**. In an interactive Windows terminal, use Up/Down to move the highlight, Spacebar to select or clear a row, and Enter to finish. If keyboard selection is unavailable, enter numbers separated by commas. `A` chooses every listed entry; Enter cancels when nothing is selected. Nothing is selected automatically. The saved plan contains only the entries you chose. Choosing a folder also includes its contents, even when the children are not separate scan suggestions. Protected paths and detected projects are kept. A higher-risk nested candidate is kept unless you explicitly select its listed entry too; the plan preview shows selected nested entries. The plan preview shows up to 12 direct items; other contents may also be removed.

After saving a plan in the guided review menu, press Enter at **Show the full cleanup preview now? [Y/n]** to list every file and folder path that passes current safety checks, with its file-data size. Large selections can take time; progress stays visible. The preview creates no backup and removes nothing. The same files can appear in more than one folder row because folder sizes include subfolders; the overall total counts each file once. The total shows file size, not guaranteed free space recovered; Windows can store file data in ways that change the amount. If the preview cannot finish, the plan stays saved and the guided menu will not offer to start cleanup; rescan or review the plan. If you skip this preview or run a saved plan later, add `-PreviewOnly` to show the full read-only preview. Cleanup repeats its checks because paths and contents can change after the preview.

If Drive Cleanr is already running as Administrator, after the preview choice it asks whether to run the new plan in that window. Enter `Y` to start it; press Enter or `N` to save it for later. If the window is not running as Administrator, Drive Cleanr says so and leaves the plan saved; if it cannot determine the status, it reports that and does not start the plan. A started guided-review plan shows your saved selection again, then asks about an optional backup and final confirmation; it does not ask you to select the same items again. Direct `--output` plan generation never runs a plan automatically.

```powershell
python analyze.py .\data\scan.csv --min-size 50 --output clean_review.ps1 --priority high
```

Use `--priority medium`, `low`, or `all` to change which review groups the plan includes. Inspect every file and folder path in the saved plan. For plans generated directly with `--output`, choose listed entries by number, choose all, or cancel when the plan runs. A plan saved from the guided review menu already contains only the items you selected and shows that saved selection again when it runs. Choosing a folder includes its contents except protected paths and detected projects. A higher-risk candidate inside the folder is kept unless you explicitly select its listed entry too; the preview shows these nested selections. The preview shows up to 12 direct items; other contents may also be removed. Cleanup progress numbers selected items in processing order and shows each item's type, label, and exact path. The first item says that nothing has been removed yet; later items say files from earlier selections may already have been removed. Each check names its current step and reports counts from the start of folder and file work, with updates during long checks. Slow file or folder content checks show the current item's path (with hidden formatting characters replaced for display), bytes checked, percentage, and overall count. Folder cleanup also skips and preserves descendants whose paths contain hidden formatting characters. Folder and ancestor project-marker checks show a running count and the current sanitized entry; project-marker and protected item names are hidden. After backup verification, folder cleanup checks for newly appeared project markers, protected paths, and links. Immediately before removing each file inside the selected folder, the plan checks that file's parent folders for project markers again. If a new marker is found, the file stays in place and cleanup stops; checks are reused only for folders that have not changed. Before removal, all selected files are inventoried and checked. The plan then checks and removes each file in turn; if a later check fails, earlier files may have been removed. Its final summary reports the files, folders, and file-data lengths removed, including partial results when a later check fails; those lengths can differ from actual free space. Large folders can take time; the plan explains each step while it works. The plan asks whether to create a verified recovery backup. Type `CLEAN` to confirm cleanup with a backup; if you decline, type `DELETE WITHOUT BACKUP` to confirm permanent removal. Any requested backup that is missing, incomplete, or fails verification stops cleanup. Use a normal PowerShell session first; use an Administrator session only if Windows denies access to a selected path. After reviewing the saved plan, `-Select 1,3 -Force` runs the cleanup without creating a backup. Add `-Backup` to create and verify a recovery backup before removal. Without a backup, removal is permanent and Drive Cleanr cannot restore the items; if backup verification fails, cleanup stops.

Saved cleanup plans do not update when Drive Cleanr changes. The plan says this when it starts, before loading its safety checks. After updating Drive Cleanr, create and review a fresh plan before running cleanup. It also says that no files have been removed while the checks load.

Drive Cleanr excludes system and personal data, and it refuses scan entries that pass through links or paths it cannot check. Before saving a plan, it verifies that every listed file or folder still matches the scan, including each selected file's scanned byte length. When the plan runs, it checks those paths and file lengths again before backup or cleanup. If a path changed, moved, changed size, or became part of a detected project, it is left in place. Selected folders keep protected and higher-risk contents. Scan again if a selected path may have changed since review.

## 4. Choose a backup and clean

After you choose the files and folders, the plan asks whether to make a verified backup. The backup gives you a way to restore selected data if cleanup affects something an app or Windows needs. If a selected target is a folder, its backup copies the folder's accessible contents, including items the cleanup will preserve, so it may need more space than the cleanup removes. If you choose yes, Drive Cleanr creates a recovery backup on a separate eligible drive before removal and verifies it against the selected items. New backups include and verify Windows alternate data streams as well as each file's usual contents. Large folders with those streams use verified direct copies instead of ZIP; if the backup destination cannot preserve them, cleanup stops. Cleanup plans also check file and folder named streams during review and immediately before removal; if a stream changes, that item is kept. If storage is unavailable or the backup is incomplete or fails verification, cleanup stops. Older backups warn that their stream contents were not verified. If you choose no, type `DELETE WITHOUT BACKUP` to confirm permanent removal. For reviewed noninteractive cleanup, `-Force` runs without a backup by default; add `-Backup` to create and verify one before removal. Without a backup, removal is permanent; `-Force` is the explicit approval to proceed after reviewing the exact plan. If you save the plan outside the project folder and choose backup, keep the project folder in place so the plan can find `backup.py`.

If you created a backup, keep it until the affected apps and Windows behave normally for an observation period. The guided restore menu shows each validated original location before it asks how to handle existing files. It refuses incomplete backups, invalid byte counts, hashless version 2 entries, and malformed, overlapping, or unsafe paths before asking for approval; legacy version 1 backups without hashes remain size/structure checked. It also refuses destinations inside or over Drive Cleanr backup folders and escapes terminal control characters in displayed paths. ZIP restore rejects Windows-invalid filename characters before writing any archive member. Restore offers overwrite or merge. Merge preserves existing files and restores missing files; overwrite replaces conflicts after you approve. During a long restore, Drive Cleanr shows byte and percentage progress for file copies, archive checks, and file verification, progress while merge checks existing-file conflicts, and a periodic status while Robocopy restores a directory. It counts an item only after that restore step finishes and reports preserved conflicts or failures separately. Before directory-copy restore starts Robocopy, Drive Cleanr checks the saved and destination folder trees for links and junctions, then repeats those checks after the existing-file conflict review; long checks show entry counts and a heartbeat with the current item at least every 10 seconds, even when one filesystem check is slow. For unattended use, `--yes` explicitly approves overwriting conflicts:

```powershell
python backup.py list
python backup.py restore --id backup_YYYYMMDD_HHMMSS_microseconds
# Explicitly approve overwriting existing files during a scripted restore
python backup.py restore --id backup_YYYYMMDD_HHMMSS_microseconds --yes
```

To remove one backup permanently, use `python backup.py delete --id <id>` and confirm the prompt. Drive Cleanr checks for links and junctions, then rechecks each opened entry as it removes it; if the safety check fails before anything is removed, it says that it removed nothing. If removal begins and then fails or is interrupted, the backup may be incomplete. Ctrl+C at a restore or delete confirmation cancels before the operation starts. Do not remove a backup until you no longer need its recovery copy.

## 5. Other useful options

```powershell
# Scan folders only; individual files will not be available to select later
python scan.py C: --folders-only

# Allow a longer run
python scan.py C: --timeout 3600

# Machine-readable review and suggested-item list
python analyze.py .\data\scan.csv --json
python analyze.py .\data\scan.csv --list-output review-items.txt

# Manage stored backups
python backup.py drive
python backup.py list
python backup.py info --id backup_YYYYMMDD_HHMMSS_microseconds
python backup.py verify --id backup_YYYYMMDD_HHMMSS_microseconds
```

## Troubleshooting a scan

- Confirm the terminal is open as administrator for WizTree's fast full-drive scan.
- Confirm `python scan.py --latest` and `python scan.py C:` use the project folder you expect.
- Set `WIZTREE_PATH` to the 64-bit `WizTree64.exe` if auto-detection fails.
- Try a longer timeout for a large drive. If Drive Cleanr cannot confirm that the scanner stopped, its incomplete export is kept under `data/.incomplete/` and excluded from previous-scan selection and retention cleanup.
- The scanner now waits for the WizTree process to exit. If it times out, note the final elapsed time and export size, then retry with a longer timeout.
