## Project shape

This is a Python command-line utility for Windows that uses WizTree or WinDirStat exports. `python drive_cleaner.py` opens a guided menu for scanning, analysis, and backup management. Automated WinDirStat scanning requires 2.6.0 or later. It is not yet a signed installer or desktop GUI. The primary user flow is scan → review report → generate PowerShell plan → confirm → backup → cleanup → observe/restore if needed.

## Current capabilities

- Guided single-command menu for scan, review, and backup management.
- WizTree and WinDirStat 2.6+ scanning, selectable at the prompt or with `--app`; both auto-detected through environment variables, local folders, common install paths, and `PATH`. Official portable builds are supported when the executable is located or configured. Scans accept a drive root or existing absolute local folder.
- WizTree exports use documented CLI options for standard or fast MFT scanning, file/folder rows, allocation sorting, drive capacity, and export depth. Automatic mode uses fast MFT for elevated whole-drive scans and standard mode otherwise; the scan mode is encoded in the export name and the review report carries the access limitation forward. The guided flow exposes scan mode, file rows, and depth. Discovery prefers a paired `WizTree64.exe` when `WIZTREE_PATH` names the 32-bit launcher so completion is tied to the export worker. WinDirStat `/SaveTo` uses the app's saved filters and scan settings. WinDirStat also supports separate load and duplicate-report modes; Drive Cleanr keeps cleanup scans on the CSV tree-export mode.
- Cleanup category and protection rules match whole Windows path components (or adjacent component sequences). Project detection recognizes common manifests and build files, Visual Studio solution/project suffixes, and user profile roots; unreadable directories are conservatively omitted.
- Automatic crash-dump candidates are restricted to known diagnostic names beneath the drive's `Windows` directory; identically named archive and project paths do not match.
- When broad and specific cleanup rules both match, the most specific path rule wins so global Gradle, Cargo, NuGet, and Go caches retain their caution-oriented package-manager labels.
- Chrome on-device model suggestions require a Chrome User Data path; NVIDIA App update artifacts require a known ProgramData updater path and stay in the caution tier.
- IndexedDB cleanup candidates require a recognized Chrome or Edge User Data profile path; arbitrary IndexedDB folder names are left unclassified.
- Generic cache/log/GPU-cache labels state that folder names are only clues, remain in the caution tier, and tell users to inspect the exact location and contents.
- Bcut (`BCUT`) cache is no longer labeled as lower-risk disposable data; if matched by the generic cache rule, it appears only as a caution item for exact-path review.
- Codex protection covers `.codex`, legacy `.codex-old` profiles, Microsoft Store package folders beginning `OpenAI.Codex_`, and `AppData\Roaming\Codex` profiles discovered in the shared candidate report.
- WinDirStat CSV parsing using its full path, logical size, physical size, and hexadecimal directory attributes plus file/folder counts.
- Candidate file/folder types are verified against the current filesystem. Missing WinDirStat type metadata uses the current path type; conflicting exported types and paths crossing junctions, symbolic links, or unreadable path components are omitted and counted. Reports and candidate lists show the source scan export timestamp and recommend rescanning if paths may have changed.
- Generated cleanup scripts recheck project markers in target ancestry before backup and immediately before removal; unreadable ancestor folders fail closed, including for single-file targets.
- When a WinDirStat export lacks volume statistics, show current local drive capacity/free space and label it as checked at analysis time.
- English-language menus, prompts, reports, and reference documentation; localized WizTree CSV column headings remain supported.
- Process-aware scan progress and configurable timeouts; Ctrl+C stops the active scanner and removes only its partial export, while prior scan exports and reviewed cleanup scripts stay until explicit cleanup.
- Scanner success requires a stable, readable CSV with recognized path and size columns; WizTree's generated-note preface is accepted without loading the whole export.
- Scan creation and retention cleanup refuse storage paths that cross symlinks, junctions, or other reparse points.
- Full scans include file rows so large individual files are visible.
- English/Chinese WizTree exports (including a generated-note preface) plus WinDirStat 2.x CSV exports; size threshold, JSON output, deduplicated candidate-list export, and interactive TUI.
- High/medium/low cleanup classifications, safety exclusions, and generated scripts for selected tiers. Downloads, Microsoft Store per-user package data, cloud/container CLI profiles, OneDrive roots (including `OneDrive - <organization>`), recovered previous-installation trees, Windows Update downloads, Windows recovery staging, update logs, Service Worker data, Codex/agent settings, and container machine state are excluded from direct cleanup. Candidate rules match exact path components or adjacent component sequences; only explicitly named dump files accept dotted filenames. Candidates under detected project roots or folders containing `.drive-cleanr-protect` are omitted; plan generation revalidates local non-root paths, reparse-point status, exclusions, project markers, selected priority, and exact rule labels for imported candidate data. Temporary-folder candidates carry an installer/build review warning, with process warnings for common browsers, editors, Java, Conda/Mamba/Pixi, Node.js, Rust, Go, .NET, Windows servicing, and package managers.
- Candidate list exports deduplicate overlapping parent/child paths across risk tiers and label the risk tier without calling any candidate guaranteed safe.
- Generated cleanup plans and candidate reports refuse to overwrite an existing file.
- Generated scripts advise least-privilege execution and let users select numbered targets, select all, or cancel. Plan indices stay attached to their original targets when another target has disappeared. Before prompting or backing up, they recheck target type and every existing ancestor for reparse points. They back up only selected targets, abort on an incomplete backup, verify the saved backup and live source match immediately before removal, recheck target type and reparse-point status, preserve nested protected data and project roots, and return a failure code if any selected cleanup fails.
- Directory cleanup also preserves nested excluded locations and detected project roots when a user selects a parent candidate, and refuses to clean directory trees containing reparse points. Tier subtotals explicitly warn that cross-tier folder overlaps affect category sums.
- Backups support files, direct directory copies, compressed directories, manifests, listing, restore, and deletion. Cleanup confirmation and the backup list show the saved backup location; discovery and direct operations reject malformed or redirected manifests, and deletion refuses backup trees containing reparse points. Partial copy/archive failures include machine-readable error details and are labeled incomplete in console output.
- Restore validates all backup payloads before writing. Files restored from direct or ZIP backups are copied and checked in a same-directory staging file before an atomic destination replace/create. Existing destination files are preserved by default; file restores skip conflicts, and directory/ZIP restores add missing files while reporting skipped conflicts. Interactive confirmation or explicit CLI `--yes` approval enables overwriting.
- Backup creation rejects drive roots and non-local or non-normalized source paths before creating backup storage.
- Backup creation also rejects sources reached through reparse points and backup roots that cross junctions; unique backup directories cannot be reused on an ID collision.
- New file, directory-copy, and ZIP backups record SHA-256 integrity fingerprints; restore checks all payloads before writing any destination. ZIP creation fingerprints the source and exact streamed archive contents so concurrent source changes mark the backup partial. Older manifests without hashes remain supported with size/structure checks and a warning. Same-size backup mismatches at creation mark the backup partial so cleanup cannot proceed.
- `backup.py verify --id <id>` checks saved payloads and current source content, with optional `--paths` to limit the check. Older backups without source fingerprints fail closed for this check.
- Large directory archives use ZIP64 and include hidden entries; restore validates all manifest targets before writing, refuses traversal/network/device targets and reparse-point redirection, and restores saved Windows attributes.
- Mock safety tests cover malformed paths, PowerShell quoting, backup failure, scan timeouts, and generated-script preservation.

## Known work / limitations

- Elevated full-drive WizTree MFT integration still needs validation on an administrator terminal. The non-elevated standard mode passed on an isolated fixture.
- The live WinDirStat scan passed on an isolated fixture and earlier on a small removable volume; a full main-drive pass and saved-filter review remain useful integration checks.
- Project detection covers common manifests and project-file suffixes; put `.drive-cleanr-protect` in the root of any unmarked project whose contents must never appear as cleanup candidates.
- Backup archive fidelity and restore behavior need a Windows integration pass with hidden/system entries and files larger than 4 GB.
- The TUI remains text-based; no installer, desktop interface, scheduled cleanup, or automatic deletion is provided.
- Review reclaimable-space estimates conservatively: hard links, busy files, and overlapping folder totals can make them differ from actual free-space changes.

## Repository hygiene

Local scan CSVs, backups, bytecode, and generated cleanup scripts are excluded from source control. Never commit scan exports or personal path data.
